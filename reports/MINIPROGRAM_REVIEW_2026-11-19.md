# 朋友圈分享与系统回归

本轮目标：补充朋友圈分享，审查并修复可复现问题，验证核心业务链路，整理后续基础能力。修改保留现有页面布局与算法。

## 本轮修复

| 问题 | 处理与验证 |
| --- | --- |
| 朋友圈分享回调缺失 | 七个注册页面统一注册 `onShareTimeline`，好友分享继续保留。开发工具实际看到朋友圈菜单及固定封面预览。 |
| 朋友圈访客不能登录，原页面依赖账户 | 场景值 1154 使用公开示例模板，跳过账户初始化和个人数据加载。实际检查公开预览及微信自带的「前往小程序」入口，进入完整小程序后恢复账户。 |
| 分享可能继承页面参数 | 朋友圈明确返回空 `query`，不传用户 ID、健康记录、设备码或挑战码，不使用当前页面截图。朋友圈路径由微信保留当前页面，好友分享固定进入首页。 |
| 账号切换共用请求缓存 | 缓存及并发合并按账户凭据区分；账户切换或清除时失效。模拟两账户验证隔离。 |
| 写入后的旧 GET 响应可能重新填入过期缓存 | 缓存增加失效代次；旧请求完成时也不能删除新的并发请求。用控制返回顺序的回归测试复现并验证。 |
| 旧账户的 401 返回可能清除新账户 | 只在请求凭据仍属于当前账户时恢复会话。回归测试验证。 |
| 首次登录失败后一直复用失败的初始化结果 | 失败后清除初始化 Promise，启动时处理拒绝；清除账户时同时清除初始化状态。临时网络失败后可重试。 |
| 合法的 0 kcal 运动记录被前端拦截 | 支持有限且非负的热量，保留空值、负数、非数字及无穷值检查；验证 0 和两位小数。 |
| `/food/create` 未检查登录 | 复用现有认证依赖及用户解析。修复前未登录请求能进入重复食物检查，修复后统一返回 401；测试复现没有创建公共垃圾食物。 |
| 补录历史体重覆盖账户当前体重 | 记录按日期、时间和 ID 排序，只有最新一条更新当前体重及微信步数消耗。历史记录仍正常入库。小程序提交后读取服务端账户，避免将历史体重直接当作当前值。新增测试先复现失败，再验证跨日、同日较早时间、无时间及相同时间的排序；网页实际补录 11 月 17 日的 75 kg 后，当前体重与趋势最新值仍为 71.8 kg。 |
| 19 项图片测试仍期待旧键名 | 对照已有精确映射更新预期，核实对应素材在网页与小程序中均存在。未通过改变生产映射迎合旧断言。 |

复现命令，在仓库根目录执行：

```powershell
node scripts/check_miniprogram_share.cjs
node scripts/check_miniprogram_session.cjs
docker cp backend/tests/. health_backend:/app/tests/
docker exec health_backend python -m pytest -q --tb=short
```

微信开发工具原生自动化就绪后，运行：

```powershell
node scripts/verify_miniprogram_runtime.cjs
```

该运行检查需要自动化端口 9420，会创建独立测试账户并保留测试记录；账号凭据仅保留在运行内存，脚本完成后恢复原账号。无需向真实好友或朋友圈发送内容。

## 已有配置与待核实项

- 已确认：本地项目 AppID 已填写，运行服务中的微信 AppID、微信密钥、非默认签名密钥和维护接口凭据均已配置。本轮只检查是否存在，没有输出或改写其值。
- 已确认：配置中的公网 API 当前可达。此结果不能证明微信后台的服务器合法域名、隐私指引、服务类目或正式发布版本已完整配置。
- 待后台核实：小程序与服务器的 AppID 一致，`request` 合法域名匹配实际 HTTPS 域名和端口，证书有效，隐私指引与微信运动授权流程一致。
- 待发布：本轮没有上传、提审或发布微信正式版。普通用户看到的新功能仍需正式版发布后生效。

## 后续建议

| 优先级 | 建议 | 当前依据 |
| --- | --- | --- |
| 高 | 首次使用先确认个人资料，再展示个人目标 | 自动账户当前填入默认年龄、性别、身高、体重等；有新手引导，但还没有完整的首次资料确认流程。 |
| 高 | 完善隐私指引查看、账户注销和个人数据导出 | 小程序目前没有这些独立入口；隐私准备文档不能替代产品内的用户入口或后台实际配置。 |
| 高 | 定期数据库备份，并做隔离环境恢复演练 | 已有备份与恢复脚本，本工作区可见最新备份为 2026-07-06；本轮未核实 NAS 是否另有自动备份，不能据此断言线上没有备份。 |
| 中 | 统一历史记录管理，支持误录后的修改或删除 | 已有饮食历史与删除，运动、睡眠、体重尚缺同等完整的历史编辑/删除入口。 |
| 中 | 加入版本更新提示与统一失败重试入口 | 未发现 `getUpdateManager` 集成；本轮已修复初始化可重试，但仍可进一步统一网络失败、空状态与重试体验。 |
| 中 | 补充反馈/帮助入口和基础运行监控 | 有维护接口与错误记录；普通用户缺少明确的问题反馈入口，定期健康检查、异常通知及备份状态仍需运维落地。 |
| 低 | 根据真实需求增加自愿订阅提醒 | 好友 PK 页面已明确微信提醒尚未接入；可后续增加授权后的提醒，不作为当前基础记录的阻塞项。 |

建议顺序：首次资料确认、隐私与数据管理、备份恢复，再完善历史记录与更新重试，最后考虑提醒类扩展。

## 验证边界

- 没有向真实好友或朋友圈发帖，没有修改真实用户健康记录。独立测试账号及其数据保留在项目数据库。
- 微信运动解密、绑定和报告统计有单元测试；Android/iOS 真机实际授权、不同微信版本的好友/朋友圈收取及正式版本体验仍需验收。
- 开发工具当前使用灰度基础库 3.16.1，曾出现来自 `WAServiceMainContext` 的 `SystemError … timeout`，堆栈未定位到项目文件。自动化导航改为等待真实回调后通过；不能据此保证所有真机环境没有 SDK 超时。
- 后端仍有 FastAPI `on_event` 和 `datetime.utcnow()` 的弃用警告，目前测试通过。后续升级依赖时可专项替换，不在本轮重构无关代码。
- 本轮覆盖主要业务与已识别问题，不代表对所有输入、网络状态、机型及所有代码路径提供“绝无 bug”的保证。
